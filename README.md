> The animations are generated by `scripts/demo.mjs`, which drives the real renderer over a
> virtual clock. They play at real time — one second of animation is one second of decoding —
> so the cadence you see is the cadence the HUD actually has. The figures are illustrative:
> they exercise the states and the colour ramp the HUD can show, and are not a benchmark.
> Regenerate with `scripts/record-demo.sh`.

## Install

```bash
pi install npm:@sven1103-agent/pi-metrics
```

Or pin a release from git:

```bash
pi install git:github.com/sven1103-agent/pi-metrics@v0.1.0
```

## Commands

| Command | Effect |
|---|---|
| `/metrics` | toggle the HUD |
| `/metrics on` · `/metrics off` | explicit toggle |
| `/metrics report` | append a table of recent calls to the transcript |
| `/metrics reset` | forget the calls recorded in this session |
| `/metrics placement above` · `below` | move the panel |
| `/metrics style compact` · `normal` | four lines, or multi-row graphs |
| `/metrics graph braille` · `block` | graph glyphs |
| `/metrics color calm` · `vivid` · `mono` | colour intensity |

Display commands take effect immediately and last until Pi exits. Each one prints the
`settings.json` line that makes the change permanent — the extension cannot write that file
itself, because Pi's extension API exposes no settings-write call, and editing the file
underneath Pi's settings manager risks dropping unrelated keys.

## Settings

All optional, under the `pi-metrics` key in `~/.pi/agent/settings.json`:

```json
{
  "pi-metrics": {
    "enabled": true,
    "placement": "aboveEditor",
    "style": "normal",
    "history": 120,
    "tpsWindow": 120,
    "tpsMax": "auto",
    "tpsGood": 30,
    "tpsBad": 15,
    "tpsFast": 100,
    "charsPerToken": "auto",
    "graphStyle": "braille",
    "colorMode": "calm",
    "timeline": true,
    "liveTimeline": true,
    "cost": true,
    "persist": false
  }
}
```

`style` is `compact` (four lines) or `normal` (multi-row graphs). `graphStyle` is
`braille` or `block`. `colorMode` is `calm`, `vivid` or `mono`. `tpsMax` is a fixed tok/s
ceiling or `auto` (session p90, with headroom, never below `tpsFast`). `charsPerToken` is `auto`
(calibrate from this session) or a fixed characters-per-token divisor. `persist` appends a
one-line card per call to the transcript. `cost` adds a cost column to `/metrics report` and
to the persisted card. It is deliberately not shown on the HUD: Pi's footer already carries a
session cost total, and a second figure derived from assistant calls alone would disagree with
it, because Pi's total also includes compaction and branch-summary usage.

`placement` accepts `aboveEditor` / `belowEditor` and, because a natural guess is otherwise
silently ignored, also `above` / `below`. A value that is unusable in any other way is
reported at startup as a warning *and* replaced by the default, so a typo cannot degrade
the HUD quietly.

The pre-0.1.0 names `rateWindow` / `rateMax` / `rateGood` / `rateBad` / `rateFast` are
still read as aliases, so an existing config keeps working. When both a legacy and a new
key are set, the new key wins.

`tpsGood` and `tpsBad` are *targets*, drawn as reference lines on the TPS chart, and
neither is printed as a number: they are configuration, not measurement, and printing them
invited reading them as results. `tpsGood` also fills the pressure bar and is the colour
baseline until the session has a few seconds of its own history. Colour is otherwise
**relative** — see below — so these thresholds do not decide it. `tpsFast` is printed because
it also floors the automatic chart ceiling.

## What it measures

- **TTFT** — request → first streamed token, as a session median. `/metrics report` splits
  it further into `conn` (request → response headers) and `prefill` (headers → first
  token) when the provider exposes the boundary; the live HUD shows the pair as its two
  session medians in milliseconds, and both show `–` otherwise. The two are separate
  statistics — medians are not additive, so they need not sum to the `med first` beside
  them. `conn` folds in server-side queueing, so the split compares calls to the *same*
  provider rather than across providers.
- **ITL** — gap between streamed deltas, as a session median and p95. This is stream
  *smoothness*, not throughput: some providers batch several tokens into one delta.
- **tok/s** — decode throughput, tagged with its source: `(usage)` when the provider
  reported `usage.output`, or `(est)` in amber while the figure still comes from streamed
  characters. A `(usage)` call is finished and its TPS buckets were rescaled to the
  provider's exact count. Estimates are never shown as if they were measured.
- **TPS** — a session timeline of tokens per second, one column per completed second,
  never reset per call so separate writing actions stay comparable. The title's left side
  is measurement (mean and p95); its right side is the chart's own axes — the recording
  window in seconds, then the tok/s ceiling, marked `auto` when derived from the session.
- **colour** — one cool-to-hot hue ramp carries the value, so throughput and latency are
  legible without comparing bar heights. It is **relative, not absolute**: severity is the
  *ratio* to the session's own typical value, so the same palette means the same thing on an
  8 tok/s local model and a 200 tok/s hosted one. Both scales are symmetric in that ratio, so a
  third of typical is the cool end, typical is the middle and three times typical is the warm
  end. `tpsGood` is only the cold-start stand-in until the session has a few seconds of history.
  The anchors run teal → green → yellow → dull red; green-to-red read as harsh, so the yellow
  half gets 70% of the warm range and only the far end reaches red. They are ordered so hue only
  ever moves one way, and every step is interpolated in Oklch rather than RGB, so the midtones
  stay saturated instead of passing through grey. In the charts the ramp is applied
  *vertically*: a bar's top edge carries the colour of its own value and the fill fades toward
  the axis baseline below. It is keyed to the **bar**, not the axis, so rescaling the axis does
  not shift existing bars' colours — an earlier version coloured each row from the axis maximum,
  which does move on its own. Only the top edge is a measurement; the cells below are a gradient.
  A braille cell holds one colour across its four sub-rows, so the fade steps once per text row.
  `colorMode` picks how loud it is: `calm` keeps the theme's own colours, `vivid` uses
  hand-picked saturated anchors, `mono` drops hue entirely. `scripts/color-ramp.test.mjs` asserts
  the order, the reach, the scale-invariance and the gradient fill.
- **usage** — the provider's own `usage.output` once a call finishes, which replaces the
  character estimate and makes that call's throughput exact. The input/cache/reasoning split
  and the session cost are not repeated here: Pi's footer already shows both, and its cost
  total includes compaction and branch-summary usage that this extension never sees.

Latency uses the **median**, throughput the **mean**, and the difference is deliberate.
Latency has a long right tail (cold connections, provider queueing) where single outliers
drag a mean away from the typical call. Throughput has no such noise: a stalled second is
delivered throughput, and a median would flatter it.

### About the character estimate

When a provider reports no usage, tokens are estimated from streamed characters divided by
`charsPerToken`. Measured across 39,000 real calls against provider-reported counts, the
true characters-per-token ranges from ~3.0 (DeepSeek) to ~3.8 (Kimi), so a fixed 4 is off
by ~19% typically and ~49% at p90. The default `auto` calibrates from the session's own
completed calls; set a number for reproducibility.

## Supported Pi versions

Each version is its own CI job, so the Checks tab names the exact release that broke:

| Pi | Typechecks clean | Loads |
|---|---|---|
| 1.3.0 · 1.2.0 · 1.1.0 | ✅ gating | ✅ gating |
| 1.0.4 · 1.0.0 · 0.99.2 | ⚠️ errors reported, not asserted | ✅ gating |
| < 0.85.1 | ❌ | ❌ does not load |

Below 1.1.0 the published typings are incomplete: the extension loads, but does not
typecheck. That lane asserts the load gate and only *reports* the error count as evidence
for the floor — it never requires errors to be present, so an upstream backport lowers the
floor without breaking the build. The `@earendil-works/pi-ai` peer floor matches at
`>=1.1.0`; the other two stay at `*` as Pi requires.

**Interactive rendering is verified manually.** The widget is TUI-only, so a headless run
cannot exercise it. Do not read these badges as covering what the HUD looks like.

## What it does not do

- It does not send anything anywhere. **No network calls, no telemetry, no credential
  access.** See [SECURITY.md](https://github.com/sven1103-agent/pi-metrics/blob/main/SECURITY.md)
  for the full scope, written against the source, and for how to report a problem privately.
- It installs nothing. `package.json` declares no runtime `dependencies`, so adding this
  package adds no code for you to audit — `npm audit` has no tree to report on for it.
- It does not measure prompt tokens per second; it measures decode throughput.
- It does not persist history across sessions unless `persist` is enabled.
